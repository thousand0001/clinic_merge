run_merge_0327.py 維護說明
================================

一、程式用途
--------------------------------
本程式用於整合診所提供的多種來源檔，依模板「選會員樣板0327.xlsx」產出：

1. 會員總表
2. 百分位名單
3. 醫生看（從會員指標內容 Key 過來）
4. 自選名單（從會員指標內容 Key 過來）

主要用途是：

1. 合併需照護名單、篩檢資料、P4P、月報表、自選/不選名單
2. 產生每位會員的整合欄位
3. 計算會員分類、分數、追蹤提醒、KPI 與百分位名單
4. 依醫事機構代碼對照診所名稱，決定輸出檔名


二、目前主力版本
--------------------------------
正式主力檔案：

- run_merge_0327.py

保留舊版參考：

- run_merge_0326_V4_3.py：run_merge_0327.py 的前身
- run_merge_0326_V4_4.py：效能實驗版，實測沒有比 V4_3 穩定更快，目前不作主力


三、輸入來源
--------------------------------
本程式支援使用者選擇「單一檔案」或「整個資料夾」。

若選資料夾，會遞迴掃描子資料夾內的來源檔。

目前支援副檔名：

- .xlsx
- .xlsm
- .xltx
- .xltm
- .csv
- .ods

掃描時會略過：

- 暫存檔（例如 ~$ 開頭）
- 舊輸出檔（例如 選會員MMDD_HHMM.xlsx）


四、主要來源檔類型
--------------------------------
1. 需照護名單
- 檔名包含「需照護名單」時，直接視為主來源「會員名單」
- 此類來源優先權最高
- 疾病樣態、ASCVD 等欄位以這類檔案為主

2. 篩檢檔
- 成人健檢
- 子宮抹片
- 老人流感
- 糞便潛血
- 肝炎篩檢

3. HealthCase
- 提供 HbA1c / LDL / UACR 結果與日期

4. P4P
- P4P收案
- P4P追蹤

5. 月報表
- R11440 類門診診療次數月報表
- 可為多工作表月份分頁
- 也可為多檔案分月
- 支援 .xlsx 與 .ods

6. 自選 / 不選會員名單
- 用於標記 E1 / E2
- 也用於補主表空白資料
- 並產生自選名單副表


五、E1 / E2 檔名辨識規則
--------------------------------
E2：

- 檔名包含「不選」
- 或檔名包含「不要」
- 或檔名包含「115X」

E1：

- 檔名包含「預選」
- 或檔名包含「自選」
- 或檔名包含「115」，但不是「115X」

若檔名有 R13210，仍優先用上述關鍵字判斷。

E1 / E2 的作用：

1. 補主表空白資料
2. 標示會員分類
3. E1 另外用於產生「自選名單」副表

注意：

- E1 / E2 不是主資料來源
- 不可覆蓋需照護名單已有內容


六、資料合併優先順序
--------------------------------
合併原則：

1. 原先空白，後面有資料，以有資料為主
2. 若來源衝突，優先順序如下：

- 需照護名單
- 會員名單
- 自選名單 / 115X / 其他補充來源

也就是：

- 自選名單、115X 只補空白
- 疾病樣態、ASCVD 以需照護名單優先


七、會員分類規則
--------------------------------
輸出欄位「會員」會出現：

- A
- B
- D
- E1
- E2
- A/E1
- A/E2
- A/E1/E2
- B/E1
- B/E2
- B/E1/E2
- E1/E2

規則如下：

1. 在需照護名單內
- 疾病樣態 = 1 / 2 / 3
- 或 ASCVD = a / b
=> 會員 A

2. 在需照護名單內，但不屬於 A
例如：
- 疾病樣態 = 4
- 或 ASCVD = 0
=> 會員 B

3. 不在需照護名單，但在自選名單
=> E1

4. 不在需照護名單，但在 115X 名單
=> E2

5. 兩者皆在時
=> E1/E2

6. 需照護名單 + E1/E2 時
=> 以 A / B 為主，再附加 E1 / E2


八、月報表用途
--------------------------------
月報表用於回填：

1. 最後就診日
2. 114年就診次數
3. 115年就診次數
4. 114年申報金額/月
5. 115年申報金額/月
6. 114年全年就診次數
7. 114年申報總金額
8. 115年申報總金額
9. 主次診斷 fallback

月報表判讀欄位重點：

- ID / 身分證號
- 日期
- 次數
- 總額 或 申請金額
- 病1 / 病23（若要抓主次診斷）


九、篩檢年度規則
--------------------------------
目前分數規則採完整年度判斷，不用月數回推。

1. 成人健檢
- 30-39歲：看 110-114 年
- 40-64歲：看 112-114 年
- 65歲以上：看 114 年

2. 子宮抹片
- 只看女性
- 25-29歲：看 112-114 年
- 30歲以上：看 114 年

3. 糞便潛血
- 45-75歲：看 113-114 年

4. BC肝炎
- 看是否曾經做過

5. 老人流感
- 65歲以上看 114 年是否做過


十、分數規則摘要
--------------------------------
總分上限 54 分，由四段組成：

1. 固定就診次數：10 分
2. 醫療費用：6 分
3. 糖心腎管理：10 分
4. 預防保健：28 分

分數說明欄位目前固定輸出為：

1. 固定就診次數：xx 分
2. 醫療費用：xx 分
3. 糖心腎管理：xx 分
4. 預防保健：xx 分

詳細規則另見：

- score_rules_54_v4_3.docx
- score_rules_54_v4_3.txt


十一、模板與輸出
--------------------------------
目前模板檔名：

- 選會員樣板0327.xlsx

輸出檔名格式：

- 診所名稱 + 選會員_ + mmdd_hhmm + .xlsx

例如：

- 王中煌診所選會員_0327_0843.xlsx

診所名稱來源：

1. 從來源資料夾名稱抓前 10 碼代碼
2. 到「醫療群_衛福部資料.xlsx」反查診所名稱

目前對照表預設位置：

- 專案目錄下的 醫療群_衛福部資料.xlsx

輸出位置：

- 被選資料夾的上層資料夾

十三、重要函式
--------------------------------
1. load_source(source_path)
- 載入來源
- 若為資料夾，會呼叫 _merge_source_folder()
- 之後建立 SourceContext

2. _merge_source_folder(folder_path)
- 掃描資料夾內所有來源檔
- 依檔名 / 工作表名歸類成標準 sheet
- 合併成暫時 workbook

3. collect_all_members(wb_src)
- 整合所有來源的人員主資料
- 以 ID 去重
- 供主表寫入

4. fill_basic_data(...)
- 把 all_members 寫入會員總表
- 是主要耗時區段之一

5. fill_external_data(...)
- 回填 ASCVD、主次診斷、篩檢、HealthCase、月報、P4P 等

6. compute_derived(...)
- 計算會員分類、分數、提醒、衍生欄位

7. compute_kpis(...)
- 計算 KPI 與百分位名單
- 同時產生醫生看、自選名單等副表


十四、目前已知耗時區段
--------------------------------
目前大型資料夾（尤其王中煌）主要耗時在：

1. load_source()
- 資料夾掃描
- workbook 載入
- 多來源 sheet 合併

2. fill_basic_data()
- all_members 寫入模板主表
- 會員數越多越明顯

V4_4 曾做過多次效能實驗，最後實測只有「月報 iter_rows(values_only=True)」這一刀相對安全。
但整體完整實測下，V4_4 仍未穩定快於 V4_3，所以目前主力仍以 run_merge_0327.py 為主。


十五、已知注意事項
--------------------------------
1. openpyxl 會遇到部分 Excel 樣式警告
- 已在主程式中隱藏「Workbook contains no default style」這類警告

2. 部分 xlsx 含有壞掉的篩選器 XML
- 已有 fallback：讀檔失敗時先移除 worksheet autoFilter 再載入

3. P4P收案 / P4P追蹤 可能有重複 ID
- 目前終端機會提醒重複 ID 狀況

4. 自選來源與 115X 來源
- 不應覆蓋需照護名單的主要欄位

5. 若未來改分數規則
- 先同步更新 score_rules_54_v4_3.docx / txt
- 再改程式


十六、維護建議
--------------------------------
1. 先保 run_merge_0327.py 為穩定版
2. 若要做效能實驗，另開新檔，不要直接改主力版
3. 每次改規則時：
- 先確認真實來源檔內容
- 再改程式
- 最後至少用一個診所資料夾完整回測
4. 若使用者說某欄位沒進來：
- 先確認來源檔是否有該欄位
- 再確認工作表是否被正確映射
- 最後確認回填函式是否有讀到標準 sheet
