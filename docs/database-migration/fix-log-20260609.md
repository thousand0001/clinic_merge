## Bug #9：115_avg_amount 計算錯誤

**檔案**：`db_pipeline/output/member_builder.py`

**問題**：O 欄分子只累加 Q1（月份 1–4）的費用，分母卻是全部 115 月數。
5 月資料進入後立即產生系統性低估。

**修正**：
```python
# 修前
"115_amount_q1":    0.0,   # 累加 month <= 4 的 amount
...
round(sums["115_amount_q1"] / month_count_115, 2)

# 修後（115_amount_q1 欄位整個移除）
round(sums["115_amount_total"] / month_count_115, 2)
```

**新增測試**（`tests/test_member_builder.py`）：
```python
def test_115_avg_includes_non_q1_months(self):
    # 月份 1（100）+ 月份 5（100）= 200 ÷ 2 = 100（舊 bug 得 50）
    self.assertAlmostEqual(m["115_avg_amount"], 100.0)
```

**commit**：`5306cab`

## Bug #10：PostgresDataProvider 不接受 published 批次

**檔案**：`db_pipeline/providers/postgres.py`

**問題**：output CLI 查詢接受 `validated` OR `published`，但 provider SQL 只過濾 `status='validated'`，選到 published 批次立即失敗。

**修正**：
```sql
-- 修前
AND b.status='validated'
-- 修後
AND b.status IN ('validated','published')
```

**commit**：`5306cab`

## Bug #11：uuid5 批次名稱不含診所代碼

**檔案**：`db_pipeline/cli/stage.py`

**問題**：`--batch-id "test"` 對不同診所產生相同 UUID，造成跨診所碰撞（已知案例：批次 `97dc477f` 混入 4 診所）。

**修正**：
```python
# 修前
uuid.uuid5(uuid.NAMESPACE_DNS, raw_bid)
# 修後
uuid.uuid5(uuid.NAMESPACE_DNS, f"{config.clinic_code}/{raw_bid}")
```

**commit**：`30f3156`

## Bug #12：批次 INSERT 衝突時不驗診所

**檔案**：`db_pipeline/storage/__init__.py`

**問題**：`ON CONFLICT (batch_id) DO UPDATE SET status='staged'` 無條件覆蓋，不同診所若 batch_id 相同會靜默污染。

**修正**：在 `_build_sql()` 前加預檢：
```python
existing = _run_query("SELECT clinic_id FROM meta.import_batches WHERE batch_id=... LIMIT 1")
if existing and int(existing) != clinic_id:
    raise ValueError("批次已屬另一診所")
```

**commit**：`30f3156`

## Bug #13：meta.source_files.batch_id 被新批次覆寫

**檔案**：`db_pipeline/storage/__init__.py`

**問題**：`ON CONFLICT ... DO UPDATE SET batch_id = EXCLUDED.batch_id` 讓每次 re-stage 都蓋掉 batch_id，導致 raw.uploaded_rows 的 source_file_id 指向已換過 batch_id 的記錄（1,901,827 筆歷史追溯斷鏈）。

**修正**：
1. 衝突策略改 `DO NOTHING`（同 sha256 → 內容未變 → 不動 batch_id）
2. 新增 `meta.batch_source_files (batch_id, source_file_id)` 聯結表，每批次顯式記錄所引用的檔案

```sql
-- DDL（已執行）
CREATE TABLE meta.batch_source_files (
    batch_id       UUID   NOT NULL REFERENCES meta.import_batches(batch_id) ON DELETE CASCADE,
    source_file_id BIGINT NOT NULL REFERENCES meta.source_files(source_file_id) ON DELETE CASCADE,
    PRIMARY KEY (batch_id, source_file_id)
);
```

驗證：安民杏翔重跑後 `meta.batch_source_files` 有 27 筆（對應資料夾 27 個來源檔）。

**commit**：`30f3156`

## Bug #14：驗證結果從未寫入資料庫

**檔案**：`db_pipeline/cli/stage.py`、`db_pipeline/storage/__init__.py`

**問題**：
- stage.py 只把 `validate_bundle()` 的結果傳給 writer，parse issues 和 raw issues 被丟棄
- writer 收到 `validation_report` 但完全不使用，`meta.validation_errors` 恆為 0

**修正**：
```python
# stage.py：合併全部 issues
full_report = ValidationReport(issues=all_issues, dataset_counts=counts)
writer.stage(..., validation_report=full_report, ...)

# storage/__init__.py：transaction 內寫入
DELETE FROM meta.validation_errors WHERE batch_id='...';
COPY meta.validation_errors (batch_id, clinic_id, table_name, row_ref, severity, error_code, message)
FROM stdin ...
```

驗證：安民杏翔重跑後 `meta.validation_errors` 有 2 筆（`unmatched_source_rows` warning + `raw_rows_not_expanded` warning）。

**commit**：`30f3156`

## Codex 審查 #2 修正（6 項，原分數 70/100）

### C2-1：migration 檔案缺失

**問題**：`meta.batch_source_files` 表建立過程未建立 migration 檔。

**修正**：新建 `db_pipeline/storage/schema/002_batch_source_files.sql`，含 DDL + 回填 SQL；已執行，回填 1095 筆。

### C2-2：is_valid 不強制執行

**問題**：`stage()` 收到含錯誤的 `ValidationReport` 時仍繼續寫入。

**修正**：在 `stage()` 起頭加守門檢查：
```python
if validation_report and not validation_report.is_valid:
    raise ValueError(f"驗證報告含錯誤，不得寫入 staging。錯誤數：{...}")
```

### C2-3：批次 INSERT 在 transaction 內 → rollback 後 status 無法更新

**問題**：批次記錄與資料在同一 transaction，rollback 後批次記錄消失，`status='failed'` 無法寫入。

**修正**：批次 INSERT 移至 main transaction 外，用獨立 `_run_sql()` 提交；ON CONFLICT 加 WHERE 保護：
```sql
ON CONFLICT (batch_id) DO UPDATE SET status='staged', started_at=now(), message=NULL
WHERE import_batches.clinic_id = EXCLUDED.clinic_id
```

### C2-4：final_status 條件化

**問題**：`UPDATE status='validated'` 寫死，不論 `validation_report` 狀態。

**修正**：
```python
final_status = (
    "'validated', validated_at=now()"
    if (validation_report and validation_report.is_valid) else "'staged'"
)
```

### C2-5：batch_source_files 冪等寫入

**問題**：重跑 staging 時 `batch_source_files` 累積舊紀錄。

**修正**：INSERT 前先 DELETE 同 batch_id 的舊紀錄：
```sql
DELETE FROM meta.batch_source_files WHERE batch_id='...';
INSERT INTO meta.batch_source_files ...
```

### C2-6：source_files 衝突策略

**問題**（已在 Bug #13 修正）：確認 `ON CONFLICT DO NOTHING` 已套用，不再覆寫 `batch_id`。
