# clinic_merge 資料庫模式遷移行動方案

## 目標

將目前以診所資料夾為輸入的 Excel 流程，逐步擴充成 PostgreSQL 資料庫模式。
遷移期間現有前置清洗、共用核心及正式 Excel 輸出必須持續可用。

## 保護邊界

在資料庫模式通過完整驗收前：

1. 不修改或取代現有正式前置清洗入口。
2. 不移除資料夾輸入模式。
3. 不改變既有 Excel 樣板、欄位順序及輸出規則。
4. 新程式放在獨立的 `db_pipeline/` 目錄。
5. 新資料表先放在獨立的 `staging_v1` schema。
6. 新輸出先寫入獨立測試目錄，不覆蓋正式輸出。
7. 每一階段均需能停用新流程並回到現有流程。

## 目標架構

```text
通用上傳入口
  -> 診所設定與系統辨識
  -> 系統解析器
  -> 標準資料集
  -> 驗證與來源覆蓋報告
  -> PostgreSQL staging_v1
  -> current/history
  -> PostgresDataProvider
  -> 現有 Excel 輸出邏輯
```

現有流程繼續保留：

```text
診所資料夾
  -> 前置清洗
  -> FolderDataProvider
  -> 現有 Excel 輸出
```

## 階段與驗收

### 第 0 階段：基準與保護

產物：

- 本行動方案。
- 正式流程保護清單。
- 代表診所與基準輸出清單。
- 新舊輸出的欄位與總額比對規格。

驗收：

- 沒有修改任何正式入口。
- 可清楚指出每一階段的回退方式。

### 第 1 階段：盤點現況

盤點：

- PostgreSQL 的 `meta`、`raw`、`audit` schema。
- 現有上傳、批次、回復及輸出紀錄。
- 各系統來源格式與現有前置清洗差異。
- PostgreSQL 特有功能及索引。

驗收：

- 形成 schema 清單與來源格式矩陣。
- 確認現有資料不需搬移或重建。

### 第 2 階段：旁路骨架

新增：

```text
db_pipeline/
  config/
  parsers/
  datasets/
  validation/
  storage/
  providers/
  cli/
```

驗收：

- 模組可匯入。
- 不依賴特定電腦絕對路徑。
- 不會寫入正式 schema 或正式輸出目錄。

### 第 3 階段：標準資料集

第一版固定資料集：

- `members`
- `monthly_claims`
- `p4p_cases`
- `p4p_tracks`
- `lab_results`
- `screenings`
- `member_selections`

每筆資料必須包含：

- `clinic_code`
- `batch_id`
- `source_system`
- `source_file`
- `source_sheet`
- `source_row`
- `raw_row_hash`

驗收：

- ID、日期、缺失值及數值欄位均已正規化。
- 每筆標準資料可追溯到來源列。
- 驗證錯誤不會寫入 current 資料。

### 第 4 階段：staging_v1 schema

原則：

- 使用 PostgreSQL。
- 以單一 transaction 寫入一個批次。
- 批次驗證通過後才更新 current。
- 保留 history 與批次回退能力。
- 不直接修改目前 `raw.current_uploaded_rows`。

驗收：

- 失敗批次可完整 rollback。
- 重跑同一批次具冪等性。
- 診所資料彼此隔離。

### 第 5 階段：解析器

建議順序：

1. SM 系統。
2. 展望系統。
3. 醫聖系統。
4. 調和系統。
5. 宏誠系統。
6. 診所自行系統。

解析器只負責：

- 讀檔及編碼處理。
- 欄位映射。
- 輸出標準資料集。
- 回報無法解析的檔案與列。

解析器不得：

- 直接產生正式 Excel。
- 直接更新 current 資料。
- 內含特定電腦絕對路徑。

### 第 6 階段：資料提供者

建立相同介面的：

- `FolderDataProvider`
- `PostgresDataProvider`

輸出層只依賴 provider，不直接掃資料夾或直接拼 SQL。

驗收：

- 同一診所可分別由資料夾與 PostgreSQL 產生相同中間資料。
- 現有資料夾模式仍可獨立執行。

### 第 7 階段：新舊輸出比對

至少核對：

- 會員有效 ID 集合。
- 會員分類與不選優先。
- `會員總表` L/M/N/O。
- `醫生看` AW:BJ。
- P4P、檢驗、篩檢及最後就診日。
- 每一類來源的輸入筆數、命中筆數及未命中原因。

驗收：

- 關鍵欄位逐 ID 一致。
- 次數與費用總額一致。
- 不允許未說明的來源遺漏。

### 第 8 階段：操作與輸出

新增：

- 通用資料夾選擇入口。
- 系統自動辨識與人工覆寫。
- 獨立輸出目錄設定。
- 批次狀態、錯誤報告及輸出紀錄。

驗收：

- 取消選擇時正常結束。
- 完成提示確認後開啟輸出。
- 輸出檔有時間戳且不覆蓋舊檔。

### 第 9 階段：切換評估

只有下列條件全數成立才規劃切換：

- 所有代表系統通過新舊比對。
- 連續正式平行運作期間沒有未解差異。
- 備份、權限、稽核及回復演練完成。
- 使用者明確同意切換。

即使切換，資料夾模式仍保留一段觀察期。

## 回退策略

每一階段的預設回退方式都是：

1. 停用 `db_pipeline` 新入口。
2. 不更新新 schema 的 current 指標。
3. 繼續使用原前置清洗與 Excel 輸出。
4. 不刪除任何 raw、staging、history 或輸出檔。
